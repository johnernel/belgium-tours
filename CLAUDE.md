# Go Belgium Tours: GoTour starter site

Server-rendered Laravel 12 landing site for Google Ads (self drive, chauffeur driven and coach tours of Belgium). It captures enquiries reliably, stores consent evidence, tracks ad sources and syncs leads to GoHighLevel (GHL). It is a skeleton the team will iterate on. **Update this file when you change anything it describes.**

## Stack
Laravel 12 / PHP 8.2+ (dev machine runs 8.5), Blade (no SPA), Tailwind v4 + Vite, Alpine.js, MySQL (SQLite in-memory for tests only), custom admin under `/admin`. No Filament, no page builders.

## Run it (XAMPP, Windows)
```
composer install && npm install
copy .env.example .env  &&  php artisan key:generate
php artisan migrate --seed && php artisan storage:link && npm run build
php artisan serve      # http://127.0.0.1:8000   (npm run dev for live CSS/JS)
```
Create the MySQL database `gobelgium` first. Details and troubleshooting: `docs/reference/LOCAL_XAMPP.md`. Admin: `/admin`, login from `ADMIN_SEED_EMAIL` / `ADMIN_SEED_PASSWORD` in `.env`.

## Business rules that are not obvious from the code
- **Enquiry form fields.** "Approximate travel date" is a native date picker (`type="date"`, opens on click via `showPicker()`, earliest = today, stored as YYYY-MM-DD). The "second quote from a partner" question was removed from the form (the `second_quote` column and GHL field stay for old enquiries).
- **One form pipeline.** Every form (hero quiz, header modal, package quote, ask-a-question, contact) uses `<x-enquiry-form>` and `POST /enquiry` (`EnquiryController` -> `EnquiryRequest` -> `EnquiryService`). JSON for the Alpine forms, plain redirect for the no-JS fallback.
- **Consent.** Required, never pre-ticked, enforced in browser and server. Wording lives in `config/gotour.php` (`consent_template`) with the company name from settings. Do not edit the words without the client's say-so, and bump `terms_version` whenever consent, Terms or Privacy wording changes. Stored per enquiry: checkbox value, exact text shown, terms version, timestamp, IP, user agent, page URL.
- **reCAPTCHA v2** is managed in **Admin > reCAPTCHA** (`RecaptchaController`, `admin/recaptcha.blade.php`): site key, secret key (stored ENCRYPTED with an `enc:` prefix in the `recaptcha_secret_key` setting, never shown again, only its last 4 characters; an older plain value still works), the "Use reCAPTCHA on my forms" switch (`recaptcha_enabled`, applies to every form) and "Test secret key" (asks Google; it cannot check the site key). Admin keys override `RECAPTCHA_*` in `.env`. It is verified server-side and fails closed while ON (Google unreachable = rejected). When switched OFF the widget, the meta tag and the server check all go away (honeypot and rate limit remain): `Recaptcha::enabled()` drives `EnquiryRequest`, the `$site->recaptcha_key/recaptcha_on` view values and the form's "keys not set" notice. The script loads on demand (first touch of a form, quiz contact step, modal open) to keep first load fast. Local `.env` uses Google's public test keys, which always pass (the screen warns when they are in use).
- **Spam.** Honeypot field `website` (filled = silent fake success, nothing saved), rate limit 6/min/IP on `/enquiry`, 5/min on admin login.
- **Tracking.** `CaptureTracking` writes plain-JSON cookies `gt_first` (never overwritten) and `gt_last` (refreshed when ad params arrive), 30 days. They are excluded from cookie encryption in `bootstrap/app.php`. Both are stored on the enquiry and sent to GHL.
- **GTM** snippet only renders when `gtm_id` is set (Admin > Settings). Events pushed: `enquiry_submit` (form_name) on submit, `enquiry_thank_you` on `/thank-you`. Attach the Google Ads conversion to the Thank You event in GTM.
- **GHL is OFF when the token or the Location ID is empty, or when it is paused.** Credentials are managed in **Admin > GoHighLevel** (`GhlController`, view `admin/ghl.blade.php`): Location ID, API token (stored ENCRYPTED with `Crypt` in the `ghl_api_token` setting and never shown again, only the last 4 characters), a "Send enquiries to GoHighLevel" switch (`ghl_enabled`), "Test connection" (passes when the token can read the custom fields, which is what the sync needs; the "View Locations" scope is optional and only adds the business name; shows GoHighLevel's own refusal message, e.g. "not authorized for this scope") and "Create missing custom fields". A pasted token is cleaned of spaces, quotes and a "Bearer " prefix before it is encrypted; the screen lists the scopes the Private Integration needs. `GhlClient::token()/locationId()` read the admin-saved values first and fall back to `GHL_API_TOKEN` / `GHL_LOCATION_ID` in `.env`. All forms share one pipeline, so saving valid credentials connects every form. Sync runs RIGHT AWAY inside the form request (`SyncEnquiryToGhl::dispatchSync`, 12 s HTTP timeout, so no queue worker/cron is needed for it to work); if it fails the enquiry is still saved, marked failed and a delayed queued retry is added (needs a worker; otherwise press Retry in Enquiries). It never fails the enquiry, retries with backoff and records status in `enquiries.ghl_*`. Field names are matched by exact name via `GhlFields`: rename in GHL and in that class together. If `APP_KEY` changes, the saved token becomes unreadable and must be pasted again.
- **Google Sheets lead feed.** Admin > Google Sheets (`SheetController`, `admin/sheets.blade.php`, `SheetClient`, job `SyncEnquiryToSheet`; guide `docs/reference/GOOGLE_SHEETS.md`): every enquiry from every form is POSTed right after the GoHighLevel step to a client-made Google Apps Script web app (script and set-up steps are on the admin screen) with a shared secret; URL and secret are stored ENCRYPTED (`sheet_webhook_url`, `sheet_secret`; only the last characters are shown), switch `sheet_enabled`. One row per enquiry, each FORM in its own tab (`SheetClient::TABS`: Main Quiz, Get Quote Popup, Package Quote, Ask a Question, Contact Form, else Other Forms; the site sends the tab name and the script creates the tab) (columns in `SheetClient::headers()`, UTM + click ids of first and last touch; IP, user agent and consent text are not sent), a NEW enquiry is inserted as row 2 right under the headings (newest first; the script does `insertRowBefore(2)`; "Send past enquiries" goes oldest first, so it ends newest on top; the client must paste the updated script into Apps Script and redeploy a new version, rows already there stay where they are), retries update the same row by Enquiry ID, cells are written as plain text (no formula injection). Status per enquiry in `enquiries.sheet_*`; failure never fails the enquiry (recorded, delayed retry, "Send to sheet" button, "Send past enquiries" 25 per click). Test row button in the admin.
- **Header & Footer code snippets.** Admin > Header & Footer (`CodeSnippetController`, `admin/snippets/*`, model `CodeSnippet`, table `code_snippets`, output class `App\Support\Snippets`): the client adds tracking pixels, scripts, styles or any HTML. Each snippet has a name, type (script / style / html), placement (`head` = before `</head>`, `body_start` = right after the opening `<body>`, `body_end` = before `</body>`, wired in `layouts/app.blade.php` only, so never in the admin), the code, "Runs on" (entire website, only these pages, or everywhere except these pages; pages are ticked from a list or typed as paths, slugs or URLs, `*` wildcard, normalised by `CodeSnippet::normalizePath`), order (lower first) and an Active switch (also toggled from the list). The code is saved and output EXACTLY as entered (no sanitising, raw `{!! !!}`); only a bare script/style that does not start with `<` is wrapped in `<script>`/`<style>`. Disabled snippets are skipped; a missing table never breaks the site. The screens carry a warning that invalid code can break the site, and sit behind the admin login (every admin user can add code). There is no Content-Security-Policy header on the site, so inline third-party code is not blocked.
